\begin{abstract}
\noindent
This specification defines an installer for macOS that leaves a person, a few
minutes after double-clicking one file, with three things running on their own
machine: a single-validator \Nd{} shard, a read-only observer node joined to it,
and the \Gz{} browser configured to deploy to the one and read from the other,
paying from a wallet that the shard's genesis has funded. It fixes the artifact
(a signed, notarised product archive, \Hr{}, carrying \Gz{} and the
\Hr{} menu-bar application, which owns the shard), the first-run provisioning sequence,
the supervision of the two nodes by a per-user launch agent, the configuration
written to each program, the security model, upgrade, reset and uninstall, the
build and release pipeline, and acceptance tests. It is grounded in a review of
\Nd{} at \code{fce422a}, \Gz{} at \code{f6ee26a} and \Camp{} at \code{b46e16c}
(with \Gz{}'s pinned \Camp{} revision \code{ea2d323}), and of the \Gz{}
architecture proposal and implementation specification in
\code{publications/f1r3gaze}. The review produced eleven findings; four of them
require small changes in \Nd{} and three in \Gz{}, specified here as work
packages.
\end{abstract}

\section{Scope and conventions}\label{sec:scope}

\subsection{What the installer delivers}

After a successful install on a supported Mac, with no further action beyond
approving a background item in System Settings when macOS asks:

\begin{enumerate}[nosep]
\item \code{/Applications/F1R3Gaze.app} and \code{/Applications/ign1t10n.app} are
  installed, signed and notarised.
\item A per-user launch agent, \code{io.f1r3fly.ign1t10n.supervisor}, is registered and
  running. It supervises two \code{f1r3node} processes: a \emph{validator} in
  standalone mode that created the shard's genesis, and an \emph{observer}
  (read-only node) that joined it over loopback.
\item The validator's key was generated on this machine at install time. The
  shard's genesis funds the user's active \Gz{} wallet.
\item \Gz{} is configured with the validator as its deploy target and the observer
  as its only observer, and is open in a window.
\item Every listening socket of both nodes is bound to the loopback interface.
\item The shard survives logout, sleep and reboot, and comes back with its chain
  intact.
\end{enumerate}

\subsection{Non-goals for this version}

Multi-validator local shards; joining a remote or public shard; exposing the local
shard to the network; Linux and Windows (the \Gz{} release already ships those
installers, but the shard bundle here is macOS-only); bundling the Embers service;
Docker. Each is compatible with the architecture below and is noted where it would
enter.

\section{Findings from the code review}\label{sec:findings}

These are the facts the design rests on. Each cites where it was established.

\begin{finding}[The observer is not optional]\label{f:readonly}
Every endpoint that runs an exploratory deploy is served only by read-only nodes;
a validator answers \code{400 readonly\_node\_required}. The list
(\code{docs/node/api-reference.md}) includes \code{POST /api/explore-deploy},
\code{POST /api/estimate-cost}, \code{GET /api/registry/\{uri\}} and
\code{GET /api/balance/\{address\}}. \Gz{}'s shard bridge uses exactly these:
it resolves sites and reads registry values at observers
(\code{gaze-shard/src/bridge.rs}, \code{graded}), quotes the cost of a deploy by
\code{estimate\_cost} on the first observer (line 276), subscribes to
\code{/ws/events} on the first observer, and sends deploys to the validator. A
standalone validator on its own therefore cannot serve the browser; the observer
is what makes the local shard readable.
\end{finding}

\begin{finding}[The browser's defaults already match the port convention]\label{f:defaults}
\code{ShardConfig::default()} is validator \code{http://localhost:40403}, observers
\code{[http://localhost:40453]}, shard id \code{root}, quorum 2, phlo price 1. The
node's documented port map puts the first node's HTTP API on 40403 and the
observer's on 40453 (\code{docker/README.md}). With one observer the bridge returns
the \emph{node} rung and never consults the quorum (\code{bridge.rs}, the
\code{obs.len() == 1} branch), so quorum 2 is harmless but misleading; the
installer writes \code{quorum = 1}.
\end{finding}

\begin{finding}[Standalone plus observer is not a shipped topology]\label{f:topology}
Standalone mode (\code{-s}, \code{standalone = true}) skips the wait for a first
peer and the heartbeat's new-parents check, and still starts the transport and
Kademlia servers (\code{node/src/rust/runtime/node\_runtime.rs}, lines 135, 404,
574; \code{heartbeat\_proposer.rs}, line 818). Nothing in the repository runs an
observer against a standalone node: \code{docker/observer.yml} bootstraps from the
multi-validator \code{shard.yml}. The join procedure itself
(\code{docs/node/joining-a-network.md}) does not depend on the peer's mode, so the
topology is expected to work, but it is unverified. See
Obligation~\ref{ob:topology}.
\end{finding}

\begin{finding}[The shipped development key is public]\label{f:devkey}
\code{docker/.env.example} (and the committed \code{docker/.env}) carry
\code{STANDALONE\_PRIVATE\_KEY}, whose public key is the only bond in
\code{docker/genesis/standalone-bonds.txt} and whose vault
\code{1111AtahZ\ldots} holds the whole standalone supply. Any install reusing it
would give every reader of the repository the validator key and the funds.
\end{finding}

\begin{finding}[How a key can reach the node]\label{f:keypath}
\code{--validator-private-key} puts the key in the process's argument vector, which
any local user can read with \code{ps}. \code{--validator-private-key-path} takes an
encrypted PEM, decrypted with OpenSSL (\code{crypto/src/rust/signatures/secp256k1.rs},
\code{parse\_pem\_file}); the password comes from the environment variable
\code{F1R3NODE\_VALIDATOR\_PASSWORD}, or else from an interactive prompt
(\code{node/src/rust/effects/console\_io.rs}). The environment of another user's
process is not readable without privilege on macOS.
\end{finding}

\begin{finding}[Everything listens on all interfaces]\label{f:bind}
\code{api-server.host} defaults to \code{0.0.0.0} (\code{defaults.conf}) and is
configurable. The protocol transport binds \code{0.0.0.0} unconditionally
(\code{comm/src/rust/transport/grpc\_transport\_receiver.rs}, line 600). On a
laptop that would expose the internal gRPC API (which proposes blocks), the admin
API and the peer protocol to whatever network the machine joins, and would trigger
the application-firewall prompt.
\end{finding}

\begin{finding}[Native linking on macOS]\label{f:linking}
The \code{crypto} crate depends on \code{openssl 0.10} without the \code{vendored}
feature, so a macOS build links Homebrew's \code{libssl}/\code{libcrypto}
dynamically; a binary built that way does not run on a Mac without Homebrew.
LMDB is compiled from source through \code{heed}; \code{aws-lc-sys},
\code{zstd-sys} and \code{bzip2-sys} link statically. \code{protoc} is a
build-time requirement only. The repository's workflows build Linux and OCI
artifacts; none builds for macOS.
\end{finding}

\begin{finding}[\Gz{} already packages itself for macOS]\label{f:gazepkg}
\code{packaging/macos/package.sh} builds a universal (\code{lipo}) bundle,
\code{io.f1r3fly.f1r3gaze}, minimum macOS 11, signs it with the hardened runtime
and \emph{empty} entitlements (there is no JavaScript, hence no JIT), wraps it in a
signed DMG, notarises and staples it. Release secrets are \code{MACOS\_CERT\_P12},
\code{MACOS\_CERT\_PASSWORD}, \code{MACOS\_SIGN\_IDENTITY}, \code{APPLE\_ID},
\code{APPLE\_TEAM\_ID}, \code{APPLE\_APP\_PASSWORD}. Wallet keys live in the
Keychain under service \code{F1R3Gaze} (\code{os-keyring}, on in release builds).
\end{finding}

\begin{finding}[\Gz{} settings: last assignment wins]\label{f:settings}
\code{settings.conf} is \code{key = value}; \code{Settings::parse} walks the lines
in order and each recognised key overwrites the previous value
(\code{gaze-shell/src/profile.rs}). If the file is absent at first load, \Gz{}
writes a commented template. A block appended at the end of the file therefore
governs the keys it sets without disturbing the rest.
\end{finding}

\begin{finding}[The browser's wallet can be funded at genesis]\label{f:wallet}
\Gz{} wallet addresses are F1R3Cap addresses, base58 of a four-zero-byte prefix,
a Keccak-derived hash and a Blake2b checksum (\code{gaze-wallet/src/address.rs}),
the same form as the vault addresses in the node's \code{wallets.txt}. The active
wallet signs, and pays for, every deploy the browser makes. Balances and transfers
go through Embers only; with \code{embers\_api} unset the wallet panel reports
that balances need Embers.
\end{finding}

\begin{finding}[Lifecycle facts]\label{f:lifecycle}
The node handles \code{SIGTERM} and \code{SIGINT} (\code{node\_runtime.rs}, around
line 908). A joined node restarted on the same data directory reconnects in about
a second; its identity is the TLS certificate in the data directory, so a data
directory must never be deleted while peers remember it
(\code{joining-a-network.md}). Log output is governed by the \code{logging} block
(sink, format, rotation, retention). The node reads \code{OPENAI\_ENABLED} and
\code{OLLAMA\_ENABLED} from the environment. \Gz{} does not yet handle
\code{f1r3://} links opened from other macOS applications (its README, ``Not in
this release'').
\end{finding}

\subsection{Principles}

\begin{principle}[Per-user, unprivileged at run time]
Administrator rights are used once, by Installer.app, to copy two bundles into
\code{/Applications}. Everything after that runs as the logged-in user. Two users
of one Mac each get their own shard.
\end{principle}

\begin{principle}[Loopback only]
No socket of either node listens on a non-loopback address. The local shard is a
private instrument, not a network service.
\end{principle}

\begin{principle}[Fresh secrets]
Every secret is generated on the user's machine at provisioning time. No key,
password or seed is shipped in any artifact.
\end{principle}

\begin{principle}[One owner for the shard]
A single supervisor starts, orders, monitors and stops both nodes. launchd keeps
the supervisor alive; the supervisor keeps the nodes alive. Two independent launch
agents were rejected because launchd has no dependency ordering and the observer's
bootstrap address depends on the validator having started.
\end{principle}

\begin{principle}[Touch only what was created]
The installer and \Hr{} never delete or overwrite data they did not create. In
particular they never remove a \Gz{} wallet, never edit \Gz{} settings outside
their own managed block, and never use \code{\textasciitilde/.rnode}.
\end{principle}

\begin{principle}[Idempotent provisioning]
Provisioning is a sequence of stages whose completion is recorded in
\code{shard.toml}. Interrupted at any point (power loss, quit, crash) it resumes at
the first incomplete stage.
\end{principle}

\section{The distribution artifact}\label{sec:artifact}

\begin{requirement}[Product archive]
The release artifact \MUST{} be a flat product archive,
\code{ign1t10n-}$v$\code{-macos-universal.pkg}, built with \code{productbuild}
from two component packages (\code{io.f1r3fly.f1r3gaze.pkg},
\code{io.f1r3fly.ign1t10n.pkg}), signed with a \emph{Developer ID Installer}
certificate, notarised, and stapled. Each component package \MUST{} install its
bundle to \code{/Applications} with bundle-version checking on, so that an
installed newer \Gz{} is not downgraded.
\end{requirement}

A DMG with two applications was considered and rejected: drag-and-drop cannot
launch anything, and the brief asks that the install end with the shard and the
browser running. A product archive delivers both bundles in one confirmation and
has a post-install hook.

\begin{requirement}[The post-install hook does one thing]
The \code{postinstall} script of the component package
\code{io.f1r3fly.ign1t10n.pkg} \MUST{} do nothing but launch \Hr{} in the console
user's session:
\begin{lstlisting}[language=bash]
#!/bin/bash
user=$(stat -f %Su /dev/console)
[ "$user" = root ] || [ -z "$user" ] && exit 0      # no GUI session: first launch will do it
uid=$(id -u "$user")
launchctl asuser "$uid" sudo -u "$user" \
  open -g -a /Applications/ign1t10n.app --args --first-run
exit 0
\end{lstlisting}
It \MUSTNOT{} create files in the user's home, register agents, or generate keys:
all of that is provisioning, performed by \Hr{} as the user (\S\ref{sec:prov}).
The script \MUST{} exit 0 even if the launch fails, so that a headless install
(MDM, \code{installer -pkg} over SSH) succeeds and provisioning happens at first
launch.
\end{requirement}

\begin{requirement}[Platforms]
The artifact \MUST{} run on Apple silicon and \SHOULD{} run on Intel
(Decision~\ref{dec:arch}); every Mach-O in it is universal. The minimum macOS is
13.0, the first release with \code{SMAppService} (Decision~\ref{dec:macos}).
\Hr{}'s \code{Info.plist} sets \code{LSMinimumSystemVersion} to 13.0; \Gz{}'s
own minimum (11.0) is unaffected, and the distribution definition sets
\code{allowed-os-versions} to 13.0 and later.
\end{requirement}

\begin{requirement}[No dynamic dependencies outside the system]
For every Mach-O in the archive, \code{otool -L} \MUST{} list only paths under
\code{/usr/lib} and \code{/System/Library}. The release pipeline enforces this
(\S\ref{sec:pipeline}); it is the check that catches Finding~\ref{f:linking}.
\end{requirement}

\subsection{One binary, three roles}

\code{ign1t10n} is written in Rust (stable 1.91, matching \Gz{}), using
\code{objc2} bindings for AppKit (status item, first-run window),
ServiceManagement (\code{SMAppService}) and Security (Keychain), \code{k256} and
\code{pkcs8} for key generation and encryption, \code{toml} and \code{serde} for
the manifest, and a blocking HTTP client for the node APIs. Rust keeps the
supervisor, the key code and the configuration generator testable on Linux CI;
only the thin UI and ServiceManagement layer is macOS-specific
(Decision~\ref{dec:lang}).

\begin{description}[leftmargin=1.5em,style=nextline]
\item[\code{ign1t10n} (no arguments)] The menu-bar application. On first run
  (\code{--first-run}, or \code{shard.toml} absent or incomplete) it opens the
  first-run window and drives provisioning. It never runs a node itself; it talks
  to the supervisor over the control socket.
\item[\code{ign1t10n supervise}] The launch agent's program. Owns the two node
  processes (\S\ref{sec:supervise}). Writes status to the control socket.
\item[\code{ign1t10n ctl} \textit{verb}] A command-line client of the control
  socket: \code{status [--json]}, \code{start}, \code{stop}, \code{restart},
  \code{logs [validator|observer|ign1t10n]}, \code{env} (prints the endpoint URLs and
  the shard id for scripts), \code{reset}, \code{uninstall}. It is what the tests
  drive.
\end{description}

The control socket is \code{run/control.sock} in the state directory, a Unix-domain
socket in a \code{0700} directory, carrying one JSON object per line. The
supervisor \MUST{} check the peer's user id (\code{getpeereid}) and refuse any
other user.

\subsection{The launch agent}

\begin{lstlisting}[language=XML]
<dict>
  <key>Label</key>              <string>io.f1r3fly.ign1t10n.supervisor</string>
  <key>BundleProgram</key>      <string>Contents/MacOS/ign1t10n</string>
  <key>ProgramArguments</key>   <array><string>ign1t10n</string><string>supervise</string></array>
  <key>RunAtLoad</key>          <true/>
  <key>KeepAlive</key>          <dict><key>SuccessfulExit</key><false/></dict>
  <key>ProcessType</key>        <string>Standard</string>
  <key>ThrottleInterval</key>   <integer>10</integer>

\code{ProcessType} is \code{Standard}, not \code{Background}: launchd throttles
CPU and I/O of background jobs, which would slow block execution. \code{KeepAlive}
restarts the supervisor after a crash but not after a deliberate stop, which exits
0. \code{ExitTimeOut} gives the supervisor time for the ordered shutdown of
\S\ref{sec:shutdown} before launchd escalates to \code{SIGKILL}.

\code{io.f1r3fly.ign1t10n} & \code{validator-pem-password} & 32 random bytes, hex; the password of \code{keys/validator.pem}\\
\bottomrule
\end{tabularx}
\end{center}

The item is created by \code{ign1t10n} and its access control list is the
application's designated requirement, so the menu bar, the supervisor and
\code{ctl} (one binary) read it without a prompt and other programs cannot. The
private key itself is never in the Keychain, never on a command line and never in
a log; it exists in plaintext only in the node's memory. \Gz{}'s wallet keys stay
in \Gz{}'s own Keychain items; \Hr{} never reads them.

%======================================================================
\section{Provisioning}\label{sec:prov}

Provisioning runs in the menu-bar process, as the user, when \code{shard.toml} is
absent or records an incomplete stage. Each stage below ends by recording itself in
\code{shard.toml}'s \code{[stages]} table; a stage that finds its postcondition
already true records itself and moves on.

\subsection{S0: preflight}
Checks: macOS $\ge$ 13; \code{F1R3Gaze.app} present with bundle identifier
\code{io.f1r3fly.f1r3gaze} and a valid signature from the same team as \Hr{};
at least 10\,GB free on the volume holding the home directory (warn below 20\,GB);
the state directory creatable. A failure stops provisioning with a specific message
and a ``Try again'' button.

\subsection{S1: ports}\label{sec:ports}
Each node needs six ports (protocol, gRPC external, gRPC internal, HTTP, discovery,
admin). The default allocation is the node's own convention, which is also
\Gz{}'s default (Finding~\ref{f:defaults}):

\begin{center}\small
\begin{tabular}{@{}lcccccc@{}}
\toprule
Node & protocol & gRPC ext & gRPC int & HTTP & discovery & admin\\
\midrule
validator & 40400 & 40401 & 40402 & 40403 & 40404 & 40405\\
observer & 40450 & 40451 & 40452 & 40453 & 40454 & 40455\\
\bottomrule
\end{tabular}
\end{center}

\noindent
A block is usable if all six ports bind on \code{127.0.0.1}. If a default block is
taken (commonly by a Docker shard from \code{docker/shard.yml}, whose ports are
published on all interfaces), try bases $b+1000k$ for $k = 1,\ldots,9$, keeping
the $+0\ldots+5$ offsets; the validator and observer are allocated independently.
The chosen bases are recorded and reused on every start; they change only on
explicit reallocation (\S\ref{sec:portfail}).

\subsection{S2: the paying wallet}
The shard's genesis must fund the wallet \Gz{} will pay with
(Finding~\ref{f:wallet}). Using the interface of work package G1:
\begin{enumerate}[nosep]
\item \code{f1r3gaze wallet active --porcelain}; if it prints an address, use it.
\item Otherwise \code{f1r3gaze wallet new "Local shard" --porcelain}, which creates
  a wallet, makes it active (it is the first), and prints its address.
\end{enumerate}
Both run the \Gz{} binary inside \code{F1R3Gaze.app} with the user's profile. The
address is recorded as \code{wallet.funded}. \Hr{} never sees the key.

\subsection{S3: the validator key}
Generate a secp256k1 key from the operating system's random source (\code{k256},
\code{OsRng}). Generate a 32-byte password, store it in the Keychain item above,
and write the key as an \code{ENCRYPTED PRIVATE KEY} PEM: PKCS\#8 with PBES2,
PBKDF2-HMAC-SHA256 (600\,000 iterations) and AES-256-CBC, which OpenSSL decrypts
and \code{Secp256k1::parse\_pem\_file} accepts (Finding~\ref{f:keypath}). Record the
uncompressed public key (\code{04}\ldots, 130 hex digits) and its F1R3Cap address.
A unit test \MUST{} round-trip a key generated this way through
\code{parse\_pem\_file} from the pinned \Nd{} revision.

\subsection{S4: genesis files}
\begin{lstlisting}[language=Conf]
# genesis/bonds.txt: <validator public key> <stake>
04a1...9e 1000
# genesis/wallets.txt: <F1R3Cap address>,<balance in dust>   (8 decimals)
<wallet.funded>,100000000000000         # 1 000 000 F1R3 for the browser's wallet
<validator address>,49900000000000000   # the rest of the dev supply: the local faucet
\end{lstlisting}
The amounts are Decision~\ref{dec:amounts}. The validator's vault is funded so that
the ``Fund wallet'' action (\S\ref{sec:ui}) can transfer to other \Gz{} wallets
later without a new genesis.

\subsection{S5: node configurations}
Render \code{conf/validator.conf} and \code{conf/observer.conf} from the bundle's
templates (Appendix A). Both set: the data directory and TLS paths inside the state
directory; the six ports; \code{api-server.host = "127.0.0.1"}; the bind address of
work package N1; the network id \code{ign1t10n-}\textit{8 random hex digits} (fresh at
each genesis, so that no other local shard can ever be mistaken for this one); the
shard name \code{root}; \code{logging} to file, JSON, daily rotation, 7 files. The
validator adds the standalone and genesis-ceremony blocks of
\code{run-local/conf/standalone.conf}; the observer disables the heartbeat and has no
ceremony block. Finality parameters (\code{fault-tolerance-threshold = 0.0}) are the
same in both.

\subsection{S6: register the agent}
\code{SMAppService.agent(plistName: "io.f1r3fly.ign1t10n.supervisor.plist").register()}.
If the status is \code{requiresApproval}, the first-run window explains that macOS
asks for approval of background items, and offers a button that calls
\code{SMAppService.openSystemSettingsLoginItems()}; provisioning waits, polling the
status each second, and continues when the status becomes \code{enabled}.

\subsection{S7: first start}
The supervisor, now running, performs its normal start (\S\ref{sec:start}) and
additionally records, from the validator's \code{GET /api/status}, the node id in
its \code{address} field, and the genesis block hash from
\code{GET /api/last-finalized-block} at height 0. The first-run window shows each
sub-step.

\subsection{S8: configure \Gz{}}\label{sec:gazeconf}
With work package G3, write \code{settings.d/50-ign1t10n.conf} in the profile.
Until G3 lands, create \code{settings.conf} from \Gz{}'s template if it is absent,
and replace (or append) the block delimited by the two marker lines below; by
Finding~\ref{f:settings} it governs the keys it sets.
\begin{lstlisting}[language=Conf]
# >>> managed by ign1t10n: do not edit inside this block >>>
validator = http://127.0.0.1:40403
observers = http://127.0.0.1:40453
shard_id = root
quorum = 1
phlo_price = 1
# <<< managed by ign1t10n <<<
\end{lstlisting}
If the profile already sets \code{validator} or \code{observers} to something other
than loopback, the first-run window asks before pointing \Gz{} at the local shard
(``Use the local shard in F1R3Gaze'', default yes). The choice is a menu toggle
afterwards; turning it off removes the block.

\subsection{S9: open the browser}
\code{open -b io.f1r3fly.f1r3gaze --args gaze://newtab}. The browser is opened only
once both nodes are ready, so that the first page a person sees can already reach
the shard. The first-run window closes with a summary: shard id, the funded wallet
and its balance, and where the logs are.

\subsection{Time budget}
Targets on an M-series Mac, measured by the acceptance suite: S0--S6 under 10\,s of
machine time (approval excluded); validator genesis to \code{/api/ready} under
60\,s; observer join to \code{/api/ready} under 180\,s (the join guide cites one to
two minutes against a healthy shard); whole first run under five minutes.

\section{Supervision}\label{sec:supervise}

\subsection{Start}\label{sec:start}
\begin{enumerate}[nosep]
\item Read \code{shard.toml}; refuse to start if the installed \code{f1r3node}
  version is incompatible with the recorded genesis version (\S\ref{sec:upgrade}).
\item Probe the recorded ports on \code{127.0.0.1}; on conflict go to
  \S\ref{sec:portfail}.
\item Fetch the PEM password from the Keychain and spawn the validator
  (argument vector below) with environment
  \code{F1R3NODE\_VALIDATOR\_PASSWORD=}\ldots, \code{OPENAI\_ENABLED=false},
  \code{OLLAMA\_ENABLED=false}, and nothing inherited beyond \code{HOME},
  \code{PATH}, \code{TMPDIR}, \code{LANG}. Stdout and stderr go to
  \code{validator.stdout.log}.
\item Poll \code{GET /api/ready} each second until 200, or fail after 120\,s
  (600\,s on the genesis start).
\item Spawn the observer with the bootstrap address built from the recorded node
  id and the validator's protocol and discovery ports, with the same filtered
  environment minus the password. Poll its \code{/api/ready} likewise (300\,s on the
  first join).
\item Report \code{Running}.
\end{enumerate}

\begin{lstlisting}
f1r3node run --standalone \
  --config-file "$STATE/conf/validator.conf" \
  --validator-private-key-path "$STATE/keys/validator.pem" \
  --host 127.0.0.1 --no-upnp --allow-private-addresses \
  --native-token-name F1R3CAP --native-token-symbol F1R3 --native-token-decimals 8

f1r3node run \
  --config-file "$STATE/conf/observer.conf" \
  --bootstrap "rnode://$NODE_ID@127.0.0.1?protocol=40400&discovery=40404" \
  --host 127.0.0.1 --no-upnp --allow-private-addresses --heartbeat-disabled \
  --native-token-name F1R3CAP --native-token-symbol F1R3 --native-token-decimals 8
\end{lstlisting}

\subsection{Health}
Every 10\,s the supervisor reads \code{GET /api/status} from both nodes and keeps
\code{isReady}, \code{lastFinalizedBlockNumber} and the peer count. The shard is
\code{Degraded} when either node is not ready, the observer has no peer, or the
observer's last finalised block trails the validator's by more than 20 blocks for
more than 60\,s. The status machine is
\code{Stopped} $\to$ \code{Starting(stage)} $\to$ \code{Running}
$\rightleftarrows$ \code{Degraded(reason)}, with \code{Failed(reason)} reachable
from any state and left only by an explicit start.

\subsection{Restarts}
A node that exits unexpectedly is restarted with exponential back-off (1, 2, 4,
\ldots, 60\,s). A validator restart does not restart the observer; the observer
reconnects on its own (Finding~\ref{f:lifecycle}). Five unexpected exits of one node
within five minutes put the shard in \code{Failed}, stop the other node, and post a
user notification pointing at the log. The supervisor never deletes a data
directory to recover.

\subsection{Stop}\label{sec:shutdown}
On \code{SIGTERM} (logout, shutdown, \code{ctl stop}, agent unregistration):
\code{SIGTERM} to the observer, wait up to 30\,s; \code{SIGTERM} to the validator,
wait up to 60\,s; \code{SIGKILL} whatever remains; exit 0. The observer stops first so
that it never sees the validator vanish mid-sync.

\subsection{Port conflicts at start}\label{sec:portfail}
If a recorded port is taken at start, the shard goes to
\code{Failed("port 40403 in use by <process>")} (the holder named via
\code{lsof}), and the menu offers ``Choose new ports''. Reallocating is safe: API
ports are only in \Gz{}'s managed block, which is rewritten; a new validator
protocol port only changes the observer's bootstrap argument. No re-genesis is
needed.

\subsection{Sleep and wake}
Nothing special is required: the nodes are processes under a launch agent, not an
application, so App Nap does not apply. After wake the heartbeat proposes on its next
interval. The supervisor \SHOULD{} hold an \code{IOPMAssertion} of type
\code{PreventUserIdleSystemSleep} only while provisioning, so a first genesis is not
interrupted by idle sleep, and never otherwise.

\section{Integration with \Gz{}}\label{sec:gaze}

\subsection{What the browser sees}
A \Gz{} configured by S8 behaves exactly as against a remote shard with one
observer: sites are resolved at the observer, answers carry the \emph{node} rung,
deploys are quoted with a cost estimated at the observer, signed by the active
wallet, sent to the validator, and followed to finalisation through the observer's
\code{/ws/events}. Pages that demand the \emph{quorum} rung receive an error
locally; that is correct, since one machine cannot provide distinct operators.

\subsection{Required changes to \Gz{}}

\begin{workpackage}[G1: porcelain wallet commands]\label{wp:g1}
\code{f1r3gaze wallet active --porcelain} prints the active wallet's address and
exits 0, or exits 3 if there is none; \code{f1r3gaze wallet new LABEL --porcelain}
prints only the new address. Both work while a \Gz{} window is open (the keystore
and \code{wallets.tsv} are safe for concurrent readers; \code{new} takes the
profile's lock file). Estimate: 0.5 engineer-week.
\end{workpackage}

\begin{workpackage}[G2: balances without Embers]\label{wp:g2}
When \code{embers\_api} is unset, the wallet panel and \code{wallet balance} read
\code{GET /api/balance/\{address\}} from the first observer (the node's own
read-only endpoint) instead of reporting that balances need Embers. Transfers still
require Embers. Estimate: 0.5 engineer-week.
\end{workpackage}

\begin{workpackage}[G3: a settings drop-in directory]\label{wp:g3}
After \code{settings.conf}, \Gz{} parses each \code{settings.d/*.conf} in the
profile in lexical order with the same last-assignment-wins rule. This lets \Hr{}
own a file instead of a block inside the user's file. Estimate: 0.25 engineer-week.
\end{workpackage}

\noindent
Registering \code{f1r3://} and \code{f1r3h://} with Launch Services is left to
\Gz{}'s own roadmap (Finding~\ref{f:lifecycle}); the installer adds nothing to
\Gz{}'s \code{Info.plist}.

\section{Upgrade, reset and uninstall}\label{sec:lifecycle}

\subsection{Upgrade}\label{sec:upgrade}
A newer archive replaces both bundles in place. The supervisor, restarted by launchd
because its executable changed, compares the new \code{f1r3node}'s storage format
(N4) with the one recorded at genesis:
\begin{itemize}[nosep]
\item \emph{compatible}: restart both nodes on their existing data;
\item \emph{incompatible}: do not start; the menu explains and offers
  ``Start a new shard'', which archives the current shard under \code{archive/}
  (\S\ref{sec:reset}) and re-provisions from S3. The wallet is kept and funded again.
\end{itemize}
A new node binary is never started against a data directory it cannot read.
\Gz{} upgrades independently of the shard.

\subsection{Reset}\label{sec:reset}
``Reset shard\ldots'' stops the shard, moves \code{validator/}, \code{observer/},
\code{genesis/}, \code{conf/} and \code{keys/} into \code{archive/<timestamp>/}
(deleting archives beyond the newest two, after confirmation, when free space is
short), deletes the Keychain item, and re-runs provisioning from S1. The dialog says
that every deploy, registry entry and balance on the local shard will be gone, that
\Gz{} wallets are untouched, and that the active wallet will be funded again.

\subsection{Uninstall}\label{sec:uninstall}
``Uninstall\ldots'' (also \code{Resources/uninstall.sh} and \code{ctl uninstall}):
stop the shard; unregister the agent; remove the state directory (after a second
confirmation, with an option to keep \code{archive/}), the logs and the Keychain
item; remove \Gz{}'s managed block or drop-in file; move \code{ign1t10n.app} to
the Trash; \code{pkgutil --forget io.f1r3fly.ign1t10n.pkg}. \Gz{}, its profile and its
wallets are left alone; the dialog says so and names the \Gz{} uninstall route
(drag to Trash) for anyone who wants it gone too.

\section{Testing and acceptance}\label{sec:accept}

\subsection{Acceptance criteria}
\begin{description}[leftmargin=1.5em,style=nextline,itemsep=2pt]
\item[A1 Clean install.] On a fresh user account of a supported Mac, opening the
  archive and completing Installer.app (plus one background-item approval) ends with
  \Gz{} open and \code{ctl status} reporting \code{Running}, within five minutes.
\item[A2 Round trip through the browser.] \code{f1r3gaze --headless} on a test page
  that deploys a registry insertion (consent granted with \code{--allow}) is signed by
  the funded wallet, reported finalised, and the inserted value is then read back at
  the observer at the \emph{node} rung.
\item[A3 Loopback only.] \code{lsof -nP -iTCP -sTCP:LISTEN} lists no socket of
  either \code{f1r3node} on an address other than \code{127.0.0.1}.
\item[A4 No foreign libraries.] \code{otool -L} on every Mach-O lists only
  \code{/usr/lib} and \code{/System} paths.
\item[A5 No shipped secrets.] The validator's public key differs from every key in
  \code{docker/.env.example}; the PEM is \code{0600}; \code{ps -Eww} run by another
  user does not reveal the password or key.
\item[A6 Persistence.] After a reboot and login, the shard returns to \code{Running}
  with the same genesis hash and a block height no lower than before.
\item[A7 Port conflict.] With \code{docker/shard.yml} running, provisioning chooses
  the next block for the validator and observer and \Gz{}'s settings name them; A2
  passes.
\item[A8 Crash recovery.] \code{kill -9} of either node leads back to
  \code{Running} without user action; six rapid kills lead to \code{Failed} and a
  notification.
\item[A9 Upgrade.] Installing $v{+}1$ over $v$ with a compatible storage format
  keeps the chain; with an incompatible one, the old shard is archived only after the
  user agrees, and the wallet is funded at the new genesis.
\item[A10 Uninstall.] After uninstall, no file under the state directory or the log
  directory, no Keychain item of service \code{io.f1r3fly.ign1t10n}, and no registered
  agent remain; \Gz{} and its wallets are untouched.
\end{description}

\subsection{Matrix}
macOS 13, 14, 15, 26 and the current release, on Apple silicon; macOS 13 and 15 on
Intel while x86\_64 is shipped. A1, A6 and A10 run on physical or virtualised
machines before each release; the others run in CI on every tag.

\section{Obligations and decisions}\label{sec:open}

\begin{obligation}[The topology works]\label{ob:topology}
Before H2 is merged, N3 must show an observer joining and following a standalone
validator. If standalone mode cannot serve the join, the fallback is to run the
validator without \code{--standalone} but with the standalone configuration's
ceremony block (it then waits for its first peer, which the observer provides), and to
make the heartbeat's new-parents check conditional on the size of the active
validator set rather than on the standalone flag.
\end{obligation}

\begin{obligation}[PEM compatibility]\label{ob:pem}
The PBES2 parameters of S3 must be accepted by the OpenSSL that N2 vendors. The
round-trip test in H1 is the proof and runs in CI against the pinned \Nd{}.
\end{obligation}

\begin{obligation}[Finalisation latency]\label{ob:latency}
The shipped standalone configuration proposes from the heartbeat with a 5\,s check
interval. A2 records the time from deploy to finalisation seen at the observer; if
the median exceeds 10\,s the validator template's heartbeat interval is revisited
(Decision~\ref{dec:heartbeat}).
\end{obligation}

\begin{decision}[Intel]\label{dec:arch}
Ship universal binaries, as \Gz{} does, or Apple silicon only, which halves the node
build time and removes an untested platform from the matrix.
\end{decision}

\begin{decision}[Minimum macOS]\label{dec:macos}
13.0, for \code{SMAppService}. Supporting 11 and 12 would require writing a plist
into \code{\textasciitilde/Library/LaunchAgents} and using \code{launchctl bootstrap},
a second code path for two releases that are out of security support.
\end{decision}

\begin{decision}[Implementation language of the UI layer]\label{dec:lang}
Rust throughout (proposed), or a Swift/SwiftUI menu bar calling the Rust
supervisor, which is less code for the window and \code{SMAppService} but adds a
second toolchain.
\end{decision}

\begin{decision}[Genesis amounts]\label{dec:amounts}
One million F1R3 to the browser's wallet and the rest of the standalone supply to the
validator's vault as a faucet; or fund every wallet \Gz{} lists at provisioning.
\end{decision}

\begin{decision}[Heartbeat interval]\label{dec:heartbeat}
Keep the repository's standalone values (5\,s check, 10\,s maximum age of the last
finalised block) or shorten them for a more responsive local shard.
\end{decision}

\begin{decision}[Cross-origin requests]\label{dec:cors}
Whether \Hr{}'s node configuration should (after a small node change) refuse HTTP
requests carrying an \code{Origin} header other than none, so that pages in other
browsers cannot use the local shard's API.
\end{decision}

\begin{decision}[Repository]\label{dec:repo}
A new \code{ign1t10n} repository (proposed), or \code{packaging/macos-local/} in the
\Gz{} repository, which would couple the shard manager's releases to the browser's.
\end{decision}

\begin{decision}[Embers]
Whether a later version bundles an Embers instance so that transfers, not just
balances, work against the local shard.
\end{decision}
